# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Kairo is a self-hosted, single-user calendar workspace: Google Calendar events, Todoist tasks, and ICS "maybe" events in one grid. TanStack Start (React 19, Vite, Nitro) + SQLite (better-sqlite3, Drizzle) + a separate background sync worker. Requires Node 24 and pnpm 10. See README.md for OAuth setup, env vars, and product behavior.

## Commands

```sh
pnpm dev                 # applies migrations, then runs Vite on :3000
pnpm worker              # background sync (separate process; run alongside dev)
pnpm typecheck           # tsc for @kairo/web only
pnpm build
pnpm test                # pnpm -r test across all packages
pnpm db:migrate
pnpm --filter @kairo/db generate   # drizzle-kit: generate a migration after editing the schema
```

CI (`.github/workflows/ci.yml`) runs `typecheck`, `build`, `test` on Node 24.

Tests use Node's built-in runner (`node:test` + `node:assert/strict`) via `tsx --test`, not Jest/Vitest. Each package's `test` script sets env vars (e.g. `DATABASE_URL=:memory:`, `ENCRYPTION_KEY`, Todoist IDs for web), so run tests through the package script rather than calling `tsx` directly:

```sh
pnpm --filter @kairo/core test
pnpm --filter @kairo/web test -- --test-name-pattern 'some test name'
```

DB-backed tests build the in-memory schema by executing every `packages/db/migrations/*.sql` file (paths are relative to the package dir), so schema changes need a generated migration before tests will see them.

## Architecture

pnpm workspace; packages export TypeScript source directly (`exports: ./src/index.ts`), with no build step between packages.

- **`packages/db`** – Drizzle schema (`src/schema/index.ts`), migrations, and a singleton `db`/`sqlite` connection. `db.ts` walks up to the workspace root to load `.env` and resolve `DATABASE_URL` (default `data/kairo.db`), with WAL and foreign keys enabled. The one-owner rule is enforced by a DB trigger (migration `0001_single-owner`).
- **`packages/integrations`** – Thin, DB-free provider clients: Google Calendar (`GoogleCalendarClient`, incremental sync, token refresh, event colors), ICS fetch/parse (`ical.js`), and Todoist. `tasks.ts` defines the provider-agnostic `TaskProvider` interface, `NormalizedTask`, and `TaskPatch`; new task providers plug in here.
- **`packages/core`** – DB-aware sync logic, all in `sync.ts`, taking `db` and provider clients as parameters so it can be tested without network access:
  - `apply*Snapshot` / `applyTaskSync` upsert provider data and commit cursors in the same transaction, so retries are idempotent.
  - A **durable job queue** in the `sync_job` table (`enqueueJob` / `leaseJobs` / `finishJob`): keyed `kind:targetId`, lease-based, with exponential backoff. Re-enqueueing a running job bumps `updatedAt` so it runs again rather than in parallel.
  - `reconcileProjection` writes a Google copy of an ICS event when the decision is Yes or Maybe. `reconcileTaskBlock` does the same for task work blocks. Both are driven by jobs so restarts don't create duplicates.
  - Task duration precedence (`effectiveTaskDuration`): user override > provider duration > AI estimate > 30-minute default.
- **`packages/ai`** – Optional AI task-duration estimates. `registry.ts` maps `AI_PROVIDER` to a factory and returns `null` unless a key is configured, so task text never leaves the server unless the user opts in. Results go in `task_estimate`.
- **`apps/web`** – The TanStack Start app plus the worker entry:
  - Server functions follow a two-file split. `server/calendar.functions.ts` declares `createServerFn` + zod validators and **dynamically imports** `*.server.ts` inside the handler, so server-only code (DB, credentials) stays out of the client bundle. Put new RPCs in the same pattern: validator in `.functions.ts`, implementation as `xxxImpl` in a `.server.ts` file.
  - `server/sync.ts` connects core to integrations. It decrypts stored credentials (`credentials.ts`, AES with `ENCRYPTION_KEY`), refreshes tokens, marks connections `reconnect` on auth failure, and defines `syncAll` and `processJobs` (dispatching the job kinds `projection`, `task-block`, and `task-push`).
  - `server/sync/worker.ts` polls every 5 minutes (`syncAll` per user) and runs AI estimates hourly. The UI's "Sync now" calls the same logic.
  - Raw HTTP routes (OAuth connect/callback, better-auth, health) live in `src/routes/api/`. `routeTree.gen.ts` is generated by the TanStack router plugin; don't edit it.
  - UI lives in `src/features/*`. Most of the calendar is in `calendar/CalendarWorkspace.tsx`, with drag-and-drop geometry in `calendar/dnd/`. Styling uses Tailwind v4 plus per-feature CSS files. Icons are `unplugin-icons` (Tabler set). `@/` is aliased to `apps/web/src`.

### Domain invariants worth knowing

- ICS events are never written to Google directly. A user **decision** (`event_decision`) produces at most one **projection** (`event_projection`) on the default or Maybe calendar. If someone edits or deletes a projection directly in Google, it becomes a conflict the user resolves in Settings (`resolveProjectionConflict`).
- Todoist tasks are mostly read-only (`data:read` scope). Task edits are stored as a pending `TaskPatch` and pushed by a `task-push` job only if the provider can write (`connectionCanWrite`). Work blocks (`task_block`) are Kairo-owned, Google-backed events, separate from the task's due date.
- Recurring Google series/occurrence editing is intentionally disabled. The timed grid uses the browser timezone.
